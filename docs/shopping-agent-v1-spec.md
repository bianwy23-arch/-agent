# Shopping Agent v1 实现规格

日期：2026-09-08。

状态：业务原则与 OpenAI Agents SDK 选型已由用户确认；本文将其汇总为实现入口。下文标为“工程默认”的接口和组织方式是待代码验证的实施方案，不代表已实现，也不冒充用户逐项确认。目前已完成小范围真实模型接入验证，尚未完成本规格全部能力；实际交付和限制见 [第二阶段接入记录](deepseek-integration.md)。

## 1. 目标与规格来源

交付个人项目规模的只读、多品类、多轮导购 Agent：根据用户需求搜索商品、查看来源证据、比较与推荐，正确处理需求变化和任务切换，以可重跑案例说明能力与限制。

本文合并轻量 PRD 的目标/范围和 spec 的工程契约，避免维护两份重复文档。详细行为以以下已确认文档为依据；本文不缩减其规则，发生冲突时应修正规格并记录原因。

- [状态更新](decision-state-design-notes.md)：需求、候选、决策、变更分组、撤销、临时探索、指代与任务隔离。
- [动作选择](action-selection-design-notes.md)：五项基础原则、七项补充原则。
- [数据范围](amazon-data.md)：12 个品类、每类 50 条、共 600 条商品元数据及可回答范围。
- [评估和简历](evaluation-and-resume-scope.md)：六项验收约定。

## 2. 第一版范围

必须覆盖：中文多轮交互；12 品类的有限商品库搜索；基于原文的证据查询与比较；正式需求修改、按范围撤销、单个临时探索方案；用户排除与系统过滤区分；展示指代；多购物任务保存但一次操作一个；追问、搜索、补证据、停止；结构化运行日志与离线验收。

推荐不表示用户选定，用户选定不表示已经购买。缺少决定性证据时可给条件性讨论，但不能作为已满足全部硬约束的主推荐。超出品类或证据范围的请求明确说明限制。

本版不做：下单支付、实时价格/库存承诺、用户评论分析、完整 SKU 报价关系、复杂多 Agent 协作、任意嵌套条件、复杂假设分支树、自由对话 LLM 用户模拟器、通用模型裁判或全功能 trace 看板。基础 Agent 对照不是交付门槛。

继续暂缓用户指定的“工具晚返回覆盖新状态”问题，不将异步结果版本隔离列入当前验收。

## 3. 已确认选型与工程默认

- **Agent 框架：OpenAI Agents SDK。** 使用单 Agent 自主工具循环，不叠加 LangGraph 或 Pi。选型理由是当前复杂度主要集中于业务状态和证据规则，采用现成循环，将业务模块独立于框架。
- **模型提供方：DeepSeek（用户于 2026-09-08 确认）。** 用户后续提供 API 凭据；具体模型 ID 可配置，接入时确认可用型号。旧代码的 DeepSeek 配置只是已有实现，不视为新框架已经兼容的证明。
- 工程默认：使用 Python 和 FastAPI；任务状态与修改记录使用本地 SQLite；商品资料使用已冻结的数据文件。具体依赖版本在接入验证后锁定。
- 框架负责模型/工具循环和运行事件。业务模块负责状态合法性、撤销、事实与资格区分、证据校验和停止结果。SDK 会话历史不作为业务状态唯一真相。
- 工程默认：同一交互按轮串行执行，状态修改按组事务提交；非法输出有限重试且应用记录去重。具体调用和超时上限配置化，在接入阶段确定，不作为业务成功标准。

## 4. 最小数据契约（工程默认）

| 对象 | 必须表达的信息 |
| --- | --- |
| 交互上下文 | 交互 ID、当前 task_id、轮次、消息和实际展示批次 |
| ShoppingTask | task_id、品类、RequirementState、CandidateState、DecisionState、待澄清项、临时探索、修改历史 |
| RequirementState | 有效要求、未知/明确无偏好、硬/软属性、值与单位、来源与原话、依赖引用、需求版本 |
| CandidateState | 商品 ID、已取得事实及证据、资格满足/违反/未知、原因、用户排除决定、依据的需求版本 |
| DecisionState | phase、focus_ids、shortlist_ids、unresolved_tradeoffs、暂时倾向/明确选择 |
| ChangeProposal | turn_id、group_id、操作、作用范围、目标、值和单位、条件/依赖、来源引用 |
| AppliedChange | 修改前后值、所属组、应用结果、被撤销记录引用；撤销本身为新记录 |
| Evidence | 商品 ID、数据版本、来源字段、原文片段；事实缺失与存在冲突分别表达 |
| TurnResult | 回答、展示商品顺序、相关证据、待澄清项、停止原因；与用户选定状态分离 |

预算使用金额与币种，不复用旧的固定人民币字段。商品价格保持历史 USD；非 USD 或币种不明确且影响筛选时不直接比较、不暗中换算，询问美元预算或先回答不依赖预算的部分。界面可解释数据口径，不要求用户理解底层协议。

恢复预算例：8000 → 9000 → 8000，第三次是当前状态的新版本，保留其间无关修改和新证据，不恢复整个历史快照。该数值例用于状态语义；真实数据任务使用明确 USD 预算。

## 5. 执行与工具契约（工程默认）

每轮先解析完整用户输入及所属任务、展示指代和表达作用，提出结构化变更；程序按依赖组校验，应用明确变化并记录待澄清部分。随后向 Agent 提供当前有效状态，由其选择动作，不预设固定追问/搜索次数或商品数量。

| 能力边界 | 输入 | 输出及约束 |
| --- | --- | --- |
| 应用状态变更 | 完整变更提议、服务端绑定的任务/轮次 | 各组已应用/待澄清/拒绝及原因；模型不能直接覆盖整个任务 |
| 搜索商品 | 品类、查询、结构化条件、正式或临时作用范围 | 搜索卡、实际过滤范围、覆盖方式；正式搜索不能暗中放宽有效硬约束 |
| 查看证据 | 商品 ID、待核实维度 | 原文证据、已知/未知/冲突；读取不自动等于满足条件 |
| 交付本轮结果 | 回答类型、候选、证据引用、未解决项、停止原因 | 程序检查 ID/引用/明确硬约束等可判定底线；不满足时返回具体问题供修正 |

工具函数名与字段枚举在首个实现切片落为类型和 JSON schema。解析、规则服务与商品工具可独立测试；隐藏评估答案不能传入这些模块。

追问通过本轮结果返回并等待下一轮输入，不让服务器执行循环无限等待用户。停止类型覆盖已回答、可推荐、需用户决定、库内无匹配、数据不足、执行受限；不能将后面几类统一记成推荐成功。

日志保存输入、配置、工具参数和结果、应用/拒绝的状态变更、证据与停止原因；不依赖保存模型隐藏思维过程。

## 6. 实施顺序与阶段验收

1. **契约与状态模块**：落实类型、持久化和组级更新；先通过预算局部恢复、独立修改保留、非法组拒绝、假设不污染正式状态的确定性检查。
2. **最小真实链路**：接入 Agents SDK 与实际模型，使用现有 Amazon 库完成输入→搜索→证据→回答。验证真实工具调用、结构化输出、错误反馈及日志。无凭据或调用失败明确报错，不静默切换为脚本成功。
3. **完整业务接入**：补齐临时探索、指代、任务切换、动作选择与无进展处理；新建网页接入新契约，展示 USD 历史价格与证据限制。
4. **全范围验收**：编制并执行 40～60 个完整任务，保留少量未调试案例，复杂子集重复运行；报告实际结果和限制，保留真实故障修复证据。

首批验收用例至少包括：

| ID | 场景 | 验收关键点 |
| --- | --- | --- |
| V1-01 | 明确美元预算内选一个商品 | 原文支持硬约束和决定性理由；不强制三个结果 |
| V1-02 | 提高预算、排除 A，再只恢复预算 | A 仍排除，新取得事实保留，资格重算 |
| V1-03 | 假设加预算 | 正式预算不变，输出标识临时范围 |
| V1-04 | 排除 A，同时预算“提高一点” | 排除立即生效，仅预算待澄清；取消澄清不恢复 A |
| V1-05 | 同轮依赖修改或非法输出 | 依赖组完整校验，重试不重复应用成功组 |
| V1-06 | 按实际展示说“第二个不要” | 绑定展示顺序，不能绑定后台新排序 |
| V1-07 | 换品类后回到原任务 | 任务条件隔离，仅继承明确指定条件 |
| V1-08 | 只比较 A/B，关键参数缺失 | 可查两者证据、不扩大搜索、不编造结论 |
| V1-09 | 价格筛选无结果与参数证据缺失 | 分别表达库内无匹配与证据不足，不混淆 |
| V1-10 | 找最便宜，存在更便宜但资格未知的商品 | 不以首个合格结果宣称全库最便宜 |
| V1-11 | 用户拒绝加预算或明确无偏好 | 不重复劝说/追问；不能自动提高预算 |
| V1-12 | 重复无进展或执行上限 | 停止并记录受限，不伪装推荐成功 |

这些是任务模板和验收条件，尚非已执行结果；制作案例时绑定真实商品、实际证据及隐藏检查条件。程序故障注入用例与真实模型任务分别计数。最终遵守评估文档的完整报告、核心回归全通过及 3 个真实问题修复记录要求，不编造故障凑数。

## 7. 开工前和接入阶段仍需落实的事项

- **具体模型 ID 和可用凭据**：提供方已确定为 DeepSeek；真实调用前落实型号和用户提供的凭据。凭据从本地环境读取，不写进文档、日志或聊天。可先完成不依赖模型的状态/工具模块。
- **工程落实**：接入阶段验证模型的工具调用与结构化输出兼容性，锁定 SDK 版本和运行上限；将本文概念字段变成 schema，不需要用户逐字段批准。
- **独立实现**：本仓库不继承旧代码、旧 Git 历史、旧术语表或 ADR。根据已确认方案新建业务模块、工具、界面与测试；运行时不能读取隐藏评估标注，不使用固定人民币字段表达 USD 价格。历史文档提到的旧实现和测试仅为背景。

以上不要求再做长篇产品调研。模型确定前可开始第一阶段；真实链路完成兼容性验证后再扩展业务，不以文档完成冒充项目交付。
