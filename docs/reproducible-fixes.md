# 本次真实复现与修复记录

日期：2026-09-10。以下来自真实 DeepSeek 调用，不把预想场景写成已发生故障。完整失败轨迹与每次复验分别保留在 `docs/validation/eval/`。

## 1. 只要一个商品却展示多个

- 触发：T03 等普通导购任务，明确“请推荐一个”。
- 修复前：development-v2/T03 返回多款；调整提示词后同轮其他品类仍发生超量展示。单靠提示词不足以稳定履行数量要求。
- 修复：交付前检查少量明确的中文数量表达（推荐一个/一款/两个/两款/三个/三款、只给同类数量）。超量退回模型修正；不设置默认推荐配额，不自动替模型删商品。
- 程序复现：`test_explicit_one_product_request_rejects_extra_recommendations`。
- 范围：不是覆盖任意语言表达的数量解析器。通过数量检查也不自动意味着商品合适；仍需资格与语义验收。

## 2. 无法核验的硬条件没有保存

- 触发：development-v2/T34，“降噪必须达到实测40dB”。
- 修复前：程序拒绝该结构化条件。模型改成文本后，重试所带的默认路由值与首轮不一致，再次被拒绝；最终状态仅剩预算，未保存降噪硬条件。回答虽然表示无法确定，状态仍然不完整。
- 修复：将“格式非法”和“当前数据无法核验”分开。格式合法的未知条件照常保存，核验结果保持 unknown。首个路由固定，修正调用可省略路由元数据，不重复开任务，也不能改到其他任务。
- 程序复现：`test_unsupported_typed_requirement_is_saved_not_dropped`、`test_group_retry_can_omit_initial_route_without_losing_task`。
- 范围：程序仍不能证明模型完整提取了每一句自然语言要求，因此 eval 另外检查硬条件是否遗漏或被弱化。

## 3. JSON 修正反馈不能帮助模型定位错误

- 触发：development-v3/T03、first-full-v4/T03，以及独立诊断重放。模型生成多余的闭合括号。
- 修复前：模型仅收到“Invalid JSON input for tool process_turn”，下一次又加错 `arguments` 包装层，连续三次失败触发上限。诊断记录确认是实际括号/嵌套错误，不是没有 API 凭据。
- 修复：返回 JSON 解码错误、行列位置和局部片段，明确工具顶层结构；不猜测修补 JSON、不自动执行未经校验的参数。依然只允许两次内部修正，第三次失败停止。错误上限原因直接保留为 schema_retry_limit，不再只显示 SDK 包装的 UserError。
- 程序复现：`test_json_retry_reports_position_and_preserves_limit_reason`。
- 范围：不能保证模型永远输出合法 JSON；执行失败仍计失败，不静默回退为脚本答案。

## 后续真实复验发现的两处修复

- **同一撤销意图被重复提交**：finalization-pilot-v7b/T26 将同句“撤销刚才的修改”拆为两个撤销组，第一组已执行，第二组报无可撤销修改，最终超时。同轮相同引用和撤销字段现按同一意图幂等处理，新增组只保留回执；undo-pilot-v8 的 T26、T46 两项均通过。不同轮次的再次撤销仍可撤销更早的修改。
- **JSON 合法但字段层级错误**：final-v8/T29 将 pending_turn_id 放在 plan 层，而 SDK 统一返回 Invalid JSON input。现区分 JSON 解码失败与模型结构验证失败，后者给出精确字段路径和类型错误，不回显完整敏感输入。schema-pilot-v9/T29 真实复验通过。

## 其他已观察问题

- **模型普通回答绕过交付工具**：first-full-v4/T31 等任务修改已生效，但模型没有调用 finish_turn。现在允许一次有限交付修正，继续沿用工具结果和状态；仍走 finish_turn 校验，并共享整轮时间、模型迭代和工具次数上限，不直接把普通文本当成功。
- **无依据的品牌保证、最优声明以及省略证据冲突**：development-v3 的自由推荐草稿包含品牌保障、未经完整资格比较的“价格最低”等内容。DOSS 音箱原文确实宣传防尘，但同时写 IPX6 与 IP66；不能把省略这种冲突的确定表述当成核验结果。主推荐现在由可信商品字段和资格结果生成，模型仍选择商品。不能据此声称所有自由回答都有自动语义证明。
- **假称全量查看**：first-full-v4/T40 声称穷举检查所有 45 款键盘，但轨迹不支持其“逐一查看全部原文”的叙述。对于带未核实硬条件的 data_limited 回答，改用状态和有限证据生成限制说明，禁止将搜索覆盖写成已经逐一阅读所有资料。
- **保留任务发现的边界缺陷**：first-full-v4/T41 未明确回应下单能力，T47 在用户要求先确认时直接选了一个预算；修复后这部分只能称为回归验证，不能继续称为未见测试。

每轮实际结果与最终复验见 [完整验收报告](evaluation-results.md)。初次失败不被单项复验覆盖；是否达到发布门槛以该报告为准。
