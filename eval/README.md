# 固定用户行为的真实模型验收

本套件共 48 个完整任务：T01–T40 为开发验收，T41–T48 为保留任务。24 个普通导购任务覆盖 12 品类的不同硬条件，其余覆盖修改、撤销、临时探索、澄清、指代、任务隔离、限定比较、无匹配、未知证据及能力边界。不是 48 个单元测试，也不是 48 轮对话。

## 运行和隔离

```bash
uv run --frozen python scripts/run_eval.py --root . --suite eval --output .runtime/eval/development --split development
uv run --frozen python scripts/run_eval.py --root . --suite eval --output .runtime/eval/holdout --split holdout
uv run --frozen python scripts/run_eval.py --root . --suite eval --output .runtime/eval/repeat --ids T25,T26,T27,T28,T29,T31,T34,T37,T46,T47
```

输出目录必须全新，避免覆盖失败记录。每个任务创建干净会话和 SQLite 文件，同一任务逐轮发送；不同任务可有限并发。模型与调用上限取本地配置，原始轨迹保存实际配置、输入、工具参数/结果、状态、停止原因、耗时和 token 用量。`provenance.json` 固定本次源码、输入与标注的哈希。

`cases.json` 只定义用户输入和用户回复分支，不定义 Agent 的工具执行顺序。T35 仅在上一轮为 needs_user 且询问美元预算时回答美元金额；分支未覆盖记为 harness_issue，需要检查脚本，不能硬编回复或直接记 Agent 失败。展示指代由本次实际输出绑定。

`gold.json` 独立保存预期状态、允许停止类型、商品允许集合及原文证据。运行中的 Agent 只有四个业务工具，没有读评估文件的工具；gold 不进入模型上下文，也不进入商品核验模块。标注基于冻结商品字段与独立规则整理，未调用生产 qualification 生成标准答案。多款满足条件的商品均可接受。`gold-authoring-v1.json` 保留开发时发现漏项的标注，不能用作最终评分。

保留任务按不同请求家族划分：交易动作、实时库存、全市场主观最优、评论原文、具体设备型号、库外品类、同轮显式预算冲突及杯制解释。它们不参与开发阶段的提示词修改。执行后不得把已查看或用于调试的任务继续称为未见任务。

## 判定

逐轮程序检查预算/币种、硬条件是否保留、允许商品集合、明确数量、引用存在、排除/撤销/假设/任务隔离状态、工具范围及允许停止原因。毫升与升、枚举 eq 与 contains 等等价表示不要求字面相同。成本不抵消错误；超时与调用上限不是成功。

语义复核另列，程序通过不等于完整通过。逐条读取回答与实际 inspect/search/process 轨迹，检查：

1. **完成当前请求**：可完成的导购给出符合条件的结果；不靠无理由追问或一律拒答通过。尊重一个/两个、只比较、不搜索、停止等范围。
2. **解释有依据**：名称、价格、决定性规格与所读原文一致；资料标注不包装成独立实测，不把品牌推断为质量保证。引用命中只证明原文存在，不自动证明回答语义受支持。
3. **状态语义正确**：不能弱化明确硬条件；修改、撤销、临时探索、排除与任务切换与原话一致。
4. **追问和停止合理**：问真正缺失的用户信息，未知事实说明证据限制；库内无匹配不外推全市场；不重推明确拒绝的方向。
5. **能力边界真实**：不承诺已下单、实时库存、当前价格、全市场最优或没有原文的评论结论。

完整通过 = 所有轮次程序通过 + 语义复核无关键错误 + 无未覆盖分支。语义复核记录必须注明执行者；编码助手复核不得描述为独立人工用户验收。独立人工复核可使用同一 rubric，但本版不伪造人工标签或用户满意度。

## 报告口径

最终报告保留初次运行、标注修正、代码修正后的验收和复杂子集重复运行。开发案例重复运行不增加独立任务数；重复结果全部列出。少量保留任务的结果不能外推真实用户成功率或每个品类的精确成功率。未实现的完整决策状态写入、推断依赖传播等不因本套件通过而算完成；用户暂缓的异步结果覆盖不在本次验收中。

## 标注修正记录

初版标注漏掉同义年龄、等价单位、部分满足条件的商品，以及撤销可使用 absent 或 no_preference 表达；原稿保存在 `gold-authoring-v1.json`。最终全量复验前，对所有完成记录且禁止搜索的轮次统一接受 answered 或 stopped：这两种交付都可结束当前轮，不代表永久关闭任务，需求/排除/探索/禁止搜索检查仍必须通过。修正前版本保存在 `gold-before-ending-equivalence.json`。早期报告保持当时的原评分，不用新标注覆盖旧失败。

沙箱网络失败还暴露了评估脚本的异常路径：上一轮无 state 时，facts_survive 检查曾崩溃。现记录 prior_state_unavailable 为失败并继续完成报告，不把缺失状态视为通过。
